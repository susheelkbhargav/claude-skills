# Glossary

**ACID** — Atomicity=abortability, Consistency=app invariants, Isolation=formally serializability, Durability=survive crash; mostly marketing term (Ch 7)
**Avro** — tagless schema binary encoding; writer/reader schemas resolved by field name (Ch 4)
**Backward compatibility** — new code reads old data (Ch 4)
**Bloom filter** — memory-efficient set approximation; says a key definitely isn't in an SSTable (Ch 3)
**Byzantine fault** — node sends arbitrary/lying messages; usually excluded in datacenter models (Ch 8)
**CAP theorem** — under partition, choose linearizability or availability; Kleppmann: avoid for precise reasoning (Ch 9)
**Causal consistency** — strongest model that stays available under partitions; partial order of happens-before (Ch 9)
**Change data capture (CDC)** — parse DB replication log, publish changes as a stream to derived systems (Ch 11)
**Clock (monotonic vs time-of-day)** — monotonic for durations; wall clock jumps, never use for ordering (Ch 8)
**Column-oriented storage** — each column in its own file; compresses via bitmap + run-length encoding (Ch 3)
**Compaction** — merging segments, keeping only newest value per key (Ch 3)
**Compound primary key** — hash first column picks partition; rest is sort order within it (Ch 6)
**Consensus** — all nodes agree on a value; equivalent to atomic commit, CAS, leader election, total order broadcast (Ch 9)
**Consistent prefix reads** — causally ordered writes seen in order; a cross-partition problem (Ch 5)
**Dirty read / dirty write** — seeing/overwriting uncommitted data; blocked by read committed (Ch 7)
**Dual-write problem** — app writes two systems separately; races and partial failures silently diverge them (Ch 11)
**Epoch number** — monotonically increasing leader-election counter (term/ballot/view); prevents split brain (Ch 9)
**Event sourcing** — app state derived by replaying an append-only log of immutable domain events (Ch 11)
**Event time vs processing time** — window on event timestamps; processor clock manufactures fake spikes (Ch 11)
**Eventual consistency** — replicas converge, lag deliberately unbounded; a liveness property (Ch 5, 8)
**Exactly-once semantics** — visible effect as-if-once: at-least-once delivery + atomic commit or idempotence (Ch 11)
**Fan-out** — requests to other services per incoming request; also write-time timeline delivery (Ch 1)
**Fault vs failure** — fault = component deviates from spec; failure = system stops serving (Ch 1)
**Fencing token** — monotonically increasing number per lock grant; resource rejects lower tokens (Ch 8)
**FLP result** — deterministic consensus impossible in the asynchronous model; timeouts rescue it (Ch 9)
**Forward compatibility** — old code reads new data by ignoring unknown additions (Ch 4)
**Hinted handoff** — sloppy-quorum writes handed back to home nodes after partition heals (Ch 5)
**Hot spot** — partition with disproportionate load (Ch 6)
**Idempotence** — safe to apply repeatedly; basis of retry safety (Ch 11)
**Lamport timestamp** — (counter, node ID); total order consistent with causality, can't detect concurrency (Ch 9)
**Last write wins (LWW)** — highest timestamp wins, rest silently dropped; only safe on immutable keys (Ch 5)
**Leaderless replication** — Dynamo-style; clients write to n replicas, quorums instead of failover (Ch 5)
**Linearizability** — single-copy illusion with recency guarantee on one object (Ch 9)
**Load parameters** — the few numbers your bottleneck depends on (req/s, fan-out distribution) (Ch 1)
**Log compaction** — keep latest value per key; a topic becomes a full DB copy (Ch 11)
**Lost update** — concurrent read-modify-write; later write clobbers earlier (Ch 7)
**LSM-tree** — memtable flushed to sorted SSTables, background compaction; random writes become sequential (Ch 3)
**MVCC** — multi-version rows with visibility rules; readers and writers never block each other (Ch 7)
**OLTP vs OLAP** — many small key lookups (seek-bound) vs few huge scans (bandwidth-bound) (Ch 3)
**Partial failure** — parts of a distributed system broken nondeterministically while rest works (Ch 8)
**Percentiles** — p50 typical, p99 tail; never average them, add histograms (Ch 1)
**Phantom** — a write changes another transaction's search result; worst on absence checks (Ch 7)
**Quorum (w + r > n)** — read and write sets overlap in ≥1 node; probabilistic freshness, not linearizability (Ch 5)
**Read committed** — no dirty reads/writes; weakest common level (Ch 7)
**Read repair** — client writes newest version back to stale replicas on read (Ch 5)
**Read skew** — seeing the DB at different points in time; fixed by snapshot isolation (Ch 7)
**Read-after-write consistency** — user sees own writes; leader reads or timestamp tracking (Ch 5)
**Rebalancing** — moving partitions between nodes; move the mapping, never hash mod N (Ch 6)
**Safety vs liveness** — "nothing bad ever" (always required) vs "something good eventually" (conditional) (Ch 8)
**Schema-on-read / schema-on-write** — implicit schema interpreted on read vs enforced on write (Ch 2)
**Secondary index (local vs global)** — per-partition (write-cheap, scatter reads) vs term-partitioned (read-cheap, async multi-partition writes) (Ch 6)
**Serializability** — transactions behave as if executed in some serial order (Ch 7)
**Serializable snapshot isolation (SSI)** — optimistic: run on snapshot, abort on detected conflict at commit (Ch 7)
**Shuffle** — partition by hash of key, sort, merge at reducers; brings related data together (Ch 10)
**Sloppy quorum** — accept writes on non-home nodes; durability without the overlap guarantee (Ch 5)
**Snapshot isolation** — transaction reads one consistent point in time; via MVCC (Ch 7)
**Split brain** — two nodes both believe they're leader; data corruption (Ch 5)
**SSTable** — key-sorted string table segment; sparse index, mergeable, compressible (Ch 3)
**System model** — explicit fault assumptions; realistic = partially synchronous + crash-recovery (Ch 8)
**Tombstone** — deletion marker so removes survive merging/compaction (Ch 3, 5)
**Total order broadcast** — messages delivered to all nodes in one fixed order; equals consensus, equals a replication log (Ch 9)
**Two-phase commit (2PC)** — prepare then commit via coordinator; blocking on coordinator crash (Ch 9)
**Two-phase locking (2PL)** — shared/exclusive locks held to commit; serializable, deadlock-prone (Ch 7)
**Version vector** — per-replica counters per key; distinguishes overwrite from concurrent siblings (Ch 5)
**Write amplification** — one logical write → many physical writes (WAL+pages, or compaction) (Ch 3)
**Write skew** — two transactions read same data, update different objects, invalidate each other's premise (Ch 7)
**Write-ahead log (WAL)** — append every change before applying; crash recovery for B-trees (Ch 3)
**Window (tumbling/hopping/sliding/session)** — fixed non-overlapping / overlapping / interval-based / inactivity-gap (Ch 11)
